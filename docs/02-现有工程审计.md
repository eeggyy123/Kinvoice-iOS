# KinVoice 现有工程审计

审计日期：2026-07-24

## 1. 结论

现有工程适合作为需求验证和后端原型，不适合直接发布。最有价值的资产是家庭组、记忆条目、AI 总结、检索和语音相关探索；最大问题是平台不符、产品主线冲突、鉴权与数据隔离不足、迁移与测试失效。

## 2. 可复用资产

- FastAPI、SQLAlchemy、SQLite 的基本服务框架。
- `Card`/`Folder` 的记忆条目原型和 7 条家庭知识示例。
- `card_summarizer` 的家庭记忆提取思路。
- FTS 检索和回答时注入家庭上下文的思路。
- 家庭采访相关的视觉语气、Cloudie 形象和系统 TTS 探索。
- 已整理的比赛获奖作品截图、2024/2025 总结和 2026 模板。

## 3. 阻断发布的问题

### 平台

- 前端是 Quick App `.ux` 工程，不是 iOS/iPadOS/visionOS 项目，不能进入 TestFlight。
- 当前环境是 Windows，缺少 Xcode、Swift、xcodegen 和 iOS 签名工具，无法在本机完成真机编译和上传。

### 产品

- `README`、`PROJECT_OVERVIEW`、帮助页和实际代码对产品核心的表述互相冲突。
- 主导航同时包含陪伴、聊天、传承和账户；设置中又独立放置音色能力，价值主线分散。
- `pages/*` 与 `components/*Tab` 存在大段重复实现，维护成本高。

### 安全与隐私

- 缺少身份 Header 时后端默认使用公共用户 `1`，不同未登录设备可能共享数据。
- `PUT/DELETE /cards/{id}` 没有按当前用户或家庭组过滤，可越权修改或删除他人条目。
- 家庭组访问密码以明文保存并通过查询接口返回。
- TTS 和音色克隆没有用户归属与授权记录。
- 帮助页声称对话只在本地、不上传第三方，但实际对话会进入后端和第三方 LLM，属于严重隐私文案不实。
- LLM 超时时间为 3600 秒，不适合移动端请求。

### 数据与迁移

- 现有 `cards_fts` 仍包含已删除的 observation/feeling/need/request 列，查询已报错。
- `migrate_category_to_folder` 仍访问已不存在的 `Card.category`，新环境初始化可能失败。
- Profile 同时使用数据库 `family_members` 与磁盘 `data/profiles/*.md` 两套来源。
- Conversation/ChatMessage 复用字段承载 AI、私聊和群聊多种语义，边界不清。

### 测试与实现漂移

- `tests/test_llm_service.py` 导入已不存在的 `normalize_history_messages`。
- `_test_summarize.py` 仍断言旧 NVC 卡片字段和旧返回值，不能验证当前接口。
- 前端 `CompanionTab` 调用未实现的 `chatAPI.deleteMessage`。
- 音色上传前端明确返回“暂未实现”；录音页面也只是提示占位。
- `requirements.txt` 未包含 `pydub`，但音频转换运行时依赖它和 ffmpeg。

## 4. 收敛策略

- 保留旧快应用代码作为原型归档，不在七天内大规模重写。
- 新建独立 SwiftUI 客户端，使用本地 SwiftData 保证核心路径不依赖服务器。
- 后端新增 `/v1` 的小而清晰接口，不让新客户端依赖旧聊天、档案和音色模型。
- `/v1` 首版保持无状态：客户端发送待整理文本或候选记忆，服务端只返回结果，不保存家庭内容。
- 生产前补 HTTPS、短超时、内容最小化日志和明确的第三方 AI 告知。

## 5. 后续清理顺序

1. 修复卡片越权、默认用户、明文家庭密码和隐私文案。
2. 重建数据库迁移与 FTS，建立可重复的集成测试。
3. 合并重复页面/组件，删除 NVC、聊天和 Profile 的历史残留。
4. 统一账户、家庭、人物、记忆、来源和授权数据模型。
5. 完成 CloudKit 或安全后端同步后，再开放多成员家庭共享和音色复刻。
